## What FlowBoard Is

FlowBoard is a containerized, TypeScript-strict, Redis-backed task management REST API. It is the capstone for the Node.js Part 2 program and must pass a Security Gate review before it ships.

Domain entities: `User`, `Board`, `Task`, `AuditLog`. Boards have one owner; tasks belong to a board; every task mutation is recorded asynchronously in an audit log via a background worker.

## Conventions

### Error Handling

- All async route handlers use `try/catch`.
- Errors are passed to `next(err)` — **never** `res.status().json()` in a `catch` block.
- HTTP errors use the `AppError` class in `api/src/errors/AppError.ts`:
  - `throw new AppError('Task not found', 404, 'TASK_NOT_FOUND')`
- A single `globalErrorHandler` is the last middleware in `app.ts`. It converts `AppError`, `ZodError`, and Prisma errors into the standard response shape.
- In production (`NODE_ENV=production`), stack traces are never returned in the response.

### TypeScript Rules

- Strict mode is on. No implicit `any`.
- All function parameters and return types are annotated.
- Prefer `interface` for object shapes; `type` for unions, intersections, and primitives.
- `Request` generics use the Zod-inferred type:
  `req: Request<z.infer<typeof TaskIdParam>>`

### Response Format

Always:

- **Success:** `{ success: true, data: ... }`
- **Error:** `{ success: false, message: '...', code: '...' }`

Standard error codes (non-exhaustive): `TASK_NOT_FOUND`, `BOARD_NOT_FOUND`, `UNAUTHORIZED`, `FORBIDDEN`, `VALIDATION_ERROR`, `RATE_LIMIT_EXCEEDED`, `NOT_READY`.

### Input Validation

- Every route that accepts a body has a Zod schema.
- Every path parameter that is an ID is `z.string().uuid()`.
- **Never spread `req.body` into Prisma.** Fields are explicitly listed via Zod-inferred types.
- Extra/unknown fields in the request body are stripped, not passed through.
- Invalid body returns `422 Unprocessable Entity` with a descriptive error.

### Authentication & Authorization

- Access token: JWT, 15-minute TTL, sent as `Authorization: Bearer <token>`.
- Refresh token: JWT, 7-day TTL, stored in Redis under `refresh:{userId}:{tokenId}`.
- **Token rotation:** every successful `POST /auth/refresh` deletes the old refresh token from Redis and issues a new pair. Reusing a refresh token returns 401.
- `POST /auth/logout` deletes the refresh token from Redis.
- The `authenticate` middleware verifies the JWT and attaches `req.user`. It does **not** hit Redis or the DB — the JWT is self-contained.
- Every route handler that touches a board or task enforces ownership: `resource.ownerId === req.user.id`, else 403.

### Redis Keys

| Purpose | Key Pattern | TTL |
| :-- | :-- | :-- |
| Rate limit (per IP) | `rate:{ip}` | 900s (15 min) |
| Refresh token | `refresh:{userId}:{tokenId}` | 604800s (7 days) |
| Task event stream | `tasks:events` (Redis Stream) | n/a |
| Dead-letter queue | `tasks:events:dlq` | n/a |

Consumer group for the Worker: `audit-group`. Consumer name: `worker-1`.

### Logging

- Pino is the only logger. No `console.log` in committed code.
- `pino-http` logs every request: method, path, status, duration.
- Redacted fields: `req.headers.authorization`, `body.password`, `body.token`, `body.refreshToken`.
- Logs are JSON in production; `pino-pretty` is used only when `NODE_ENV=development`.

### Background Worker

- The Worker is a separate Node.js process. It has no HTTP server.
- It reads `tasks:events` via `XREADGROUP` in batches.
- On success: write `AuditLog` row, then `XACK` the message.
- On failure: retry up to 3 times. After the 3rd failure, move the message to `tasks:events:dlq` and `XACK` the original so it does not loop forever.

### Security Middleware Stack (order matters)

In `app.ts`, before any routes:

1. `helmet()` — security headers
2. `cors({ origin: process.env.ALLOWED_ORIGINS?.split(',') ?? [...], credentials: true })`
3. `express.json({ limit: '10kb' })`
4. `app.set('trust proxy', 1)` — Nginx is in front
5. `pino-http` request logger
6. Rate limiter on `/auth/login` and `/auth/register` only
7. Routes
8. `globalErrorHandler` — last

## Non-Negotiable Rules for the AI

These rules override anything the AI might suggest by default:

1. **Never spread `req.body` into Prisma.** Whitelist fields explicitly via Zod.
2. **Never return stack traces in production responses.** Check `NODE_ENV`.
3. **Never write `res.status().json()` inside a `catch` block.** Use `next(err)` + `AppError`.
4. **Never put secrets in code.** All sensitive values come from environment variables; `.env.example` documents every required key.
5. **Never call `console.log` in committed code.** Use the Pino logger.
6. **Never store passwords in plaintext or with weak hashing.** bcrypt, cost factor ≥ 12.
7. **Never skip Zod on a route that accepts data.** No exceptions for "it's just an internal endpoint."
8. **Never let a refresh token live without a TTL.** Every Redis key tied to auth has an `EXPIRE`.
9. **Never let the Worker swallow a failed message silently.** 3 retries, then DLQ.
10. **Never accept generated code you cannot explain.** If a line is unclear, ask before committing.
